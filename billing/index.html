🔒 Custody Boundary

What the runtime holds — and what it doesn't

✅

What the runtime holds

  • The opaque uid reference (a mapping only you can resolve)
  • The app_name attribution tag
  • The execution count, timestamp, and duration
  • Async workflow state (encrypted, with TTL)
  • Encrypted auth tokens (never plaintext)
❌

What the runtime never holds

  • Customer names, emails, or phone numbers
  • Order history or menu contents
  • Pricing, discounts, or policy data
  • API request or response bodies (default)
  • Plaintext credentials or session tokens
Default retention: zero. API requests and responses are not stored unless the CRM explicitly opts in per-API. Session history is opt-in and lives in the CRM's own storage, not Sageion's.
🚪

The runtime is designed to lose your billing business

The moment your CRM has its own billing system, you should stop paying Sageion for attribution. Point your finance stack at the metering export, and we'll get out of the way. There's no contractual bundling, no data portability puzzle, no migration project. The primitive is designed for exit — because a Restaurant CRM should never be locked into a billing layer they don't want.
