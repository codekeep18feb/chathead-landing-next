Enterprise OAuth Flow

Tenant-owned accounts. Zero shared credentials.

Each tenant brings their own Google Workspace, Slack, or HubSpot account. Sageion never sees a password — only an OAuth token, encrypted per-tenant, in its own Secrets Manager namespace.

What's inside

  • ✓PKCE + state + audience + issuer verification
  • ✓Refresh-token rotation with race-condition detection
  • ✓Revoke at provider AND delete locally
  • ✓Narrowed-scope propagation on refresh
  • ✓7-day grace window during token rotation
  • ✓Per-tenant secrets under {Prefix}/sageion/oauth-token/*
Proof: A CISO can audit exactly which secrets belong to which tenant.

Isolated Security Surface

Separate stack. Separate IAM. Separate secrets.

The connector handler runs on its own Lambda, its own API Gateway, its own SQS queue with DLQ, and its own IAM role. OAuth credentials never mix with tenant data. Credential rotation is one CloudFormation deploy.

What's inside

  • ✓Own Lambda with 60s timeout (vs AutoBot's 180s)
  • ✓Own SQS queue with 5-receive DLQ, 14-day retention
  • ✓Own Secrets Manager namespace for provider credentials
  • ✓Read-only IAM on AutoBot's data tables
  • ✓Narrow write IAM on connector's own tables only
  • ✓No shared environment variables with AutoBot
Proof: The compliance auditor sees two separate stacks, not one.

🔄 How It Works

From OAuth to Execution in Three Steps

1

Connect

The tenant admin clicks Connect Google (or Slack, or any future provider). PKCE, state, audience, and issuer are all verified automatically.

Token stored in {Prefix}/sageion/oauth-token/... — encrypted, tenant-scoped, never shared.
2

Define

The admin builds a named connector definition — e.g. "Send WhatsApp confirmation" — and fills in its parameters from the auto-generated schema form.

Definitions are tenant-scoped. Apps attach the ones they need. Nothing auto-inherits.
3

Fire

Attach the definition to any chain node or leadgen form. It fires to a separate SQS queue with its own DLQ, in parallel with the main flow.

A slow Slack API never delays a table booking. Failures go to the DLQ, not to the user.
🛡️ Security

Isolated by Design.

The connector stack runs on its own deployment — separate IAM, separate secrets, separate queue. OAuth credentials never mix with tenant data.

Separate Lambda

60-second timeout, narrow IAM, dedicated execution role. Cannot access AutoBot's data except through read-only paths.

Separate Secrets Namespace

Provider credentials live at {Prefix}/sageion/oauth-provider/*. Tenant tokens live at {Prefix}/sageion/oauth-token/*. Never shared.

Separate SQS Queue

With a dedicated DLQ. Failures retry 5 times, then archive to DLQ with 14-day retention — visible to operations, never to the end user.

Read-Only Cross-Domain Access

The connector can read -AutoBotData and -ScopeAttachments to verify ownership. It can never write to either.
