The Interface

The SDK is a thin client over the runtime that's already in production. It authenticates with your tenant API key, dispatches the intent, and returns the workflow's correlation ID. That's it.

TypeScriptserver.ts
import { SageionClient } from "@sageion/server-sdk";

const sageion = new SageionClient({
  apiKey: process.env.SAGEION_API_KEY,
  tenantId: "your-tenant-id",
});

// Fire a workflow from your backend code
const execution = await sageion.trigger({
  intent: "refund_approval",
  appName: "store_42",
  payload: {
    orderId: "ORD-12345",
    amount: 249.99,
    reason: "cold_food_complaint",
  },
});

console.log(execution.correlationId); 
// → "8a2c9f7e-..." — track this execution anywhere

// Async workflows return immediately; poll or webhook for completion
if (execution.status === "paused_for_approval") {
  // Your manager approval flow handles the rest
}
Same runtime, same authentication, same audit trail. The SDK uses the tenant API key that already exists. Every execution appears in the same dashboard as a chat-triggered one. There is no "server-triggered" silo — it's the same system.

Every Guarantee Holds. Regardless of Trigger Source.

Durable async

A server-triggered chain that pauses for approval uses the same DynamoDB state row. Resume works identically.

Zero data storage

Server-triggered requests are not saved unless the tenant explicitly opts into history for that API.

Deterministic execution

The SDK triggers a chain. The chain is deterministic. The LLM is never invoked from the backend path.

Full audit trail

Every execution carries app_name and intent, whether it originated from a user or from code.
