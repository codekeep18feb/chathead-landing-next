What "Runtime" Actually Means Here

⏳

Durable Async

The model doesn't wait. A workflow pauses, its state lands in DynamoDB, and the request returns. When the webhook arrives, the workflow resumes exactly where it stopped.

In a framework, you write this. Retry logic, state persistence, resumption, correlation IDs — all yours.

🔌

Connectors

Slack, Sheets, Gmail, Calendar, and every future integration ship as schema-driven operations. The admin form is generated. No frontend deploy.

In a framework, every connector is a new library, a new auth flow, a new UI form. You own it forever.

💰

Metering, Not Custody

Every execution carries app_name and uid. That's the entire billing surface. You build the invoice, not the pipeline. The runtime never holds PII, order history, or pricing — only a reference you can resolve.

In a framework, you build both the metering and the custody layer. Every dollar of revenue needs a data pipeline.

🛡️

Isolated Security

Per-tenant Secrets Manager namespaces. RSA + AES-GCM token encryption. Connector runs on its own Lambda with its own IAM. No cross-contamination.

In a framework, you build the entire secrets layer. One misconfig and the blast radius is every tenant.

📊

Billing Attribution

Every execution carries app_name and user_id. The metering export drops directly onto the CRM's invoice. No reconciliation pipeline.

In a framework, you own the attribution layer. Every dollar of revenue requires a data pipeline.

Ship in Days. Not Quarters.

You don't pay us for the framework. You pay us for the runtime that ships with it — and the years of infrastructure engineering baked in.
